The one thing that needed repairing

T6 (#19) got an independent review because it narrows a machine-frozen public API. The reviewer found the removal was correct and that it had dropped something else on the way out:

await supportedDuelCardCodes() was doing a second, undocumented job — it held the deck listing until loadCatalog's callback, registered first on the same memoised promise, had assigned deckBuilderCatalog.

Without it the listing does only IndexedDB work and finishes inside the window of 129 shard fetches. A returning player whose saved deck is a local one, pressing Start while the catalog is still loading, would re-list against an empty catalog → every local deck fails to resolve → the bundled default is written to localStorage and the fallback notice raised. The catalog lands seconds later, the deck reappears in the list, but the choice is gone permanently — the notice is only ever set true and nothing restores the key.

Same path also reached ensureStarterDeck with an empty catalog and persisted a Starter Deck whose stored validation was 40 missing-card errors.

26089da restores the ordering with a direct await runtimeCatalog() and a comment saying why the wait exists, so it is not deleted again as a redundant await. Both faults have red-first tests.
