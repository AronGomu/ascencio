Default Deck Selection — storage → editor → duel menu

Feedback General-1. Plan ai-artifact/PLAN_2026_08_16_decks_feedback.md T14/T15 · ADR-038. Complements deck-selection-architecture.html (resolution/validation flow unchanged).

Flow

1 · Seed (first run)

ensureStarterDeck() (src/decks/starter-deck.ts): no default set → adopt existing "Starter Deck" or create it from bundled player.ydk → setDefaultDeck(id).

Idempotent, best-effort. Called by editor mount and duel picker listing.

2 · Assign (library)

Deck Library row action Set default → preferences["default-deck"]. Badge marks the row. Deleting the deck clears the preference.

3 · Consume (duel menu)

Picker resolves default id → selectable key local:{id}:{rev}. Player seat pre-selected. Opponent fixed preset:shaddoll.

Player-seat selection precedence

  1. Persisted key (ygo.ui.v2 → decks.playerKey) when it still resolves against the listed selectable decks.
  2. Stored default deck's key, when the deck resolves ready and all codes are duel-supported.
  3. Bundled fallback preset:mvp-player (+ fallback notice only when a previously chosen deck vanished).

Opponent seat

  • Auto-assigned Shaddoll (DEFAULT_OPPONENT_DECK_ID = "shaddoll"). Feedback names a "Shadow deck"; Shaddoll is the assumed match — no such preset exists otherwise.
  • No opponent picker rendered; stale persisted opponent keys rewritten to preset:shaddoll.
  • "For now": a later plan may reopen opponent choice; the persisted field survives for that.
