# T31: Set-image pipeline

**Plan:** `./artifacts/PLAN_2026_08_20_duel_vn_feedback.md`
**Depends:** T1
**Commit outcome:** A script downloads every shop set's official image into `generated/`, records a sha256 manifest, and a verifier fails the build if the bytes drift.

## Context (self-contained)

- Goal: land `feedback-duel.md` and `feedback-vn.md` as one ticket chain on `main`. This ticket is `feedback-vn.md` shop item 1.
- This slice: acquisition and verification only. The shop keeps rendering text tiles until T32 consumes the images.
- Out of scope here: the grid layout (T32), card art (T33), any change to the card-image pipeline.
- Assumptions in force: the upstream is YGOPRODeck, already this project's card-image source; images land in `generated/` (git-ignored), are sha256-verified at build time, and are served as plain static runtime URLs in the ADR-039 style rather than through the duel's verified snapshot; sets with no upstream image get a typographic tile at render time.

## Requirements

- `node scripts/download-set-images.ts` reads the shop set list, fetches each set's image, writes `generated/set-images/{setId}.jpg` and a manifest `generated/set-images/manifest.json` of `{ setId, sha256, bytes, sourceUrl }`.
- Sets whose upstream record has no `set_image` are recorded in the manifest under `missing: string[]` and are **not** an error.
- `node scripts/verify-set-images.ts` re-hashes every file and exits non-zero on a mismatch, a missing file or a manifest/file set disagreement.
- The images are exposed at runtime as `{BASE_URL}runtime/sets/{setId}.jpg`, wired through the same Vite runtime-assets mechanism the card images use.
- An offline run with the files already present verifies without network access.

## Inputs

- `public/story/shop-sets.v1.json` — the 50-set list, generated by `scripts/generate-shop-sets.ts`; each entry has `id`, `name`, `releaseYear`, `released`, `cards`.
- `scripts/generate-shop-sets.ts:464` — the existing upstream call pattern: `https://db.ygoprodeck.com/api/v7/cardinfo.php?cardset=<name>`.
- Upstream for set art, verified reachable: `https://db.ygoprodeck.com/api/v7/cardsets.php` returns records of `{ set_name, set_code, num_of_cards, tcg_date, set_image? }`, where `set_image` is `https://images.ygoprodeck.com/images/sets/{CODE}.jpg` (checked: `LOB` → `HTTP/2 200`, ~72 KB; `STAX` has no `set_image`).
- `scripts/lib/images.ts`, `scripts/lib/files.ts`, `scripts/lib/model.ts` — the existing download, hashing and record helpers used by `scripts/download-images.ts` and `scripts/verify-images.ts`; copy their structure, including the run lock in `scripts/lib/run-lock.ts`.
- `scripts/lib/vite-runtime-assets.ts` — how `runtime/images/{code}.jpg` reaches the dev server and the build; the set images follow the same route under `runtime/sets/`.
- `scripts/lib/active-image-manifest.ts` — the card-image manifest shape to mirror.
- `package.json` scripts block — where `assets:images` and `assets:images:verify` are declared.
- Tests: `tests/images.test.ts`, `tests/sources.test.ts` (legacy `node --test` suite), plus `tests/unit/` for pure helpers.
