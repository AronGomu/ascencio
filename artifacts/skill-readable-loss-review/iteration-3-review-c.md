# Explanation from C for execution

## 1. Outcome and scope

Improve one `ai-bot` against frozen opponents, including starting self-opponent; deliver accepted source, results and history. Preserve engine, decks, legality and information boundaries. Unchanged completion is valid; suspension remains incomplete. Use `session-typescript/v1`; verify gates, persist through tools.

## 2. Process overview

Prepare identities, limits and recommendations; evaluate baseline, decide, analyze. Then replay corrections, assemble, evaluate, decide and analyze again. Consolidation waits for evaluation/decision. Analyze final evaluation. No passing correction ends normally; exhaustion suspends.

## 5. Limits and accounting

| Resource/stage | Default limit | Override rule | Accounting | Action at exhaustion |
|---|---|---|---|---|
| Decisions/matches | 50; 250 total four-game matches | Pin owner values | Exclude baseline decisions; distribute matches evenly with ordered remainder | Analyze final decision, deliver |
| Evaluation games | `(1 + decisions) × matches × 4` | Recovery floor 10% | Reservations count; caches add none | Ignore remaining after allowance |
| Wall/storage | 24 hours; 50 GB | Explicit complete effective limits | Include downtime/imports; reserve 16 MB control | Suspend |
| Deadlines | Evaluation 5h; preparation 10m; validation/replay 5m; shutdown 60s | Effective configured values | Include replay prefix; remaining-wall cap | Applicable incident policy |
| Worker calibration | 2 through logical CPUs | Owner recalibration permitted | Local paths govern recommendation reuse | No qualifier stops Prepare |
| Replay stack | 300 distinct losses/rule | No extra budgets implied | Eligible at five; pass five wins AND 5%, choice changed | Valid failure at cap discards rule |

## 6. Incidents and continuation

| Incident | Immediate action | Retry allowance | Evidence preserved | Resume condition |
|---|---|---|---|---|
| Individual timeout | Report and finalize ignored | Never retry case | Timeout and denominator | Continue safe jobs |
| Evaluation interruption | Recover missing work | Within recovery allowance | Attempts and completions | Remaining resources |
| Calibration stage failure | Fresh directory | One retry, then count exclusion | Both attempts/exclusions | Exact compatible identity |

| Unsupported package | Adapt build/validation only | Fresh validation | Failed validation | Protected boundaries hold |
| Resource/owner/analyst stop | Stop; bounded shutdown, settle/checkpoint | No implicit extension | Claims/budgets | Applicable explicit authorization |
