# Explanation from reviewer-b for prospective refinement execution

## 1. Outcome and scope

I would produce a complete, shorter, readable sibling skill package that preserves the supplied skill’s intent, dependencies, essential behavior and output contracts. Required input is the skill folder; optional priorities, iteration count, destination and review context govern execution. Success requires completing the requested iterations, resolving comprehension disagreements, validating affected behavior and delivering the candidate with external evidence. This document describes that process without executing it.

## 2. Process overview

I would establish the behavioral baseline and explain the incoming skill before editing. Each outer iteration simplifies the candidate, then enters an inner verification and fresh-review loop. Corrections return to verification and three new explanations until no misunderstanding remains. I would record counts and findings before the next simplification iteration. Linked authoring rules supply deletion audits, boundary walkthroughs and accounting requirements; their mutual refinement dependency is a reading dependency, not another invocation.
