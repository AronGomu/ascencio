# Explanation from i1-c for local calibration skill execution

## 1. Outcome and scope

Given one target `ai-bot`, optional additional opponents, owner limits and an optional compatible checkpoint, improve its paired-game win rate against frozen opponents including its starting self. Successful completion delivers the accepted source, verified results and compact attempt history, or honestly retains the starting/accepted source when no edit qualifies. Only target AI changes; decks, engine, legality and hidden-information boundaries remain protected. This explanation reads only the supplied skill package and explanation template; it executes no workflow or gameplay and does not verify external owning tools.

## 2. Process overview

Prepare pins setup, budgets, sources, schedule, analysis policy and two local calibration recommendations. Evaluate first measures the starting bot, then combined candidates; finalized slices may feed bounded diagnosis while evaluation continues. Decide records the baseline reference or candidate decision, and Analyze always completes the required source-bound review. If decisions remain, select ordinary improvement or regression repair, replay isolated rules against the appropriate current analysis source, accumulate pending cases, assemble passing edits and repeat evaluation. The decision ceiling or no qualifying edit leads to delivery; resource and other stop incidents suspend at a verified checkpoint. The dispatcher is stateless: project tools own persisted gates, transactions, accounting and publication.

## 4. Identities and invariants

| Item | Initial source/value | Allowed changes | Must remain fixed | Verification |
|---|---|---|---|---|
| Comparisons | Frozen opponents include starting target; separate accepted incumbent | Accepted reference moves after promotion | Opponent order, source hashes, paired starting inputs, engine/content/runner/comparison identity | Complete non-ignored paired intersection; every opponent has a completed pair |
| Scoring | Game wins / completed non-ignored games; draws zero wins in denominator; equal opponent weighting | Candidate outcomes | Strict improvement authority; no confidence intervals or selected-subset promotion | Paired coverage/rates/differences and ignore counts/reasons |
| Ordinary mode | Baseline, accepted candidate, tie or unassessable rejection | Add one fix per isolated variant | Analysis/control/assembly base = accepted source | Rejected evaluation still analyzed before retained accepted analysis is reused |
| Regression repair | Valid lower paired candidate rate | Remove/update one existing rule, add none | Analysis/control/base = regressing candidate; unedited rules preserved; comparator still accepted | Candidate losses only; paired new-loss metadata ranks associations, not causality |
| Pending rule | Stable reason/aliases, rule ID and exact semantic hash, original cases | Explicit semantic alias reconciliation; new cases up to 300; new correction gets new identity | Original inputs/log hashes/decision/choice provenance; current-source replay binding | Fresh controls and rule branches; never force historical choices into current-policy control |
| Completed local calibration | `.cache/typescript-native-workers.json`, `.cache/replay-workers.json` | Recalibrate on owner request or unusable file/count | Paths are reuse keys; positive integer count within logical CPUs | Read local count; source/runtime/fixture/version changes or missing old evidence do not invalidate it |
| Unfinished calibration | Exact attempt identity/output directory | Resume same identity; failed stage gets fresh-directory retry | Attempt history, pinned inputs and exclusions | Revalidate retained evidence; completed recommendation reuse is a different rule |
| Models and formats | gpt-6.1-sol, low unless user settings; session-typescript/v1 | Honor explicit model settings, report unavailable controls | Existing campaign/round/incumbent keys/paths; gameplay typed `.log`, generated JSON via scripts | Validate current runner and generated bindings |

## 5. Limits and accounting

| Evaluation | 250 four-game matches, 1,000 games/evaluation | Total allocation floor(total/opponents), remainder to first opponents; require at least one each; leave matchesPerOpponent unset | Planned games = (1 + effective decisions) × matches × 4; recovery floor(10% planned); reserve and settle failed/interrupted attempts; reuse adds zero | Recovery exhausted: ignore remaining interrupted games, continue eligible work without extra games |

| Storage | 50,000,000,000 bytes | Always explicit stop.maxBytes; authorized increase through writer-locked gate then continuation when session lock releases | Logical staging/log/evidence/import bytes; fixed 16,000,000 control reserve within cap | Stop admissions/data writes, retain quota marker and required evidence |
| Stage deadlines | Evaluation 18,000,000; preparation 600,000; validation 300,000; replay including prefix 300,000; shutdown 60,000 ms | Effective pinned timeouts | Replay controls/takeovers/calibration diagnostics separate from evaluation but consume wall/storage | Incident-specific handling |
| Rule replay | No replay-game quota; all associated cases required; 300 distinct cases per reason/rule | No implied extra decisions/time/storage | Re-executions do not add distinct cases; ignored timeouts remain denominator, never convert | Pending or blocked on incomplete evidence; never proven-discarded by exhaustion |

## 6. Incidents and continuation

| Incident | Immediate action | Retry allowance | Evidence preserved | Resume condition |
|---|---|---|---|---|

| Interrupted evaluation | Recover missing work inside resources/deadlines | Automatic only within 10% game allowance | Verified completions and every attempt/reservation/timeout | Compatible evidence and remaining allowance |
| Failed calibration count stage | Fresh directory, same pinned inputs | One retry; interrupted attempt consumes attempt; second failure excludes count and remaining repetitions | attempts.json, both attempts, measurements/manifests/exclusions | Exact identity for unfinished resume; integrity/resource/owner incidents propagate |
| Unsupported package before admission | Preserve validation; adapt build/validation tooling only; related local checks and fresh validation | No evaluation/recovery charge | Failed and fresh validation | Valid protected boundaries or stop |
| Initialization/sideboarding/integrity/other non-timeout validation | Stop; resolve integrity/input-prefix first and ask owner if unresolved | No generic retry; ordinary replay no automatic allowance | Diagnostics, source bindings, safe checkpoint | Resolved validity and applicable authorization |
| Time/storage exhaustion | Suspend; stop admission and owned groups after bounded grace, settle/cancel reservations | No automatic increase | Required evidence, interrupted/pending work, budgets | Explicit increase/continuation with complete effective limits |
| Owner pause/cancel or analyst execution failure | Stop owned work, preserve claims/uncovered losses | No automatic restart | Owner-stop token where required, operation identity and claims | Explicit instruction on same verified checkpoint; no duplicate owners |
| Dead wrapper/uncertain children | Verify owner death, child birth identities and lock token | Explicit child termination only with bounded grace | Operation snapshots/heartbeat/outcomes | Fail closed without reliable identity; shell exit/PID alone insufficient |
