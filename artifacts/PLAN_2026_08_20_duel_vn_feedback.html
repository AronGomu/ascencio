Goal

Land feedback-duel.md (10 items) and feedback-vn.md (shop, card list, reveal, general, collection) as one ticket chain on main.

The round is not cosmetic. It fixes a duel-killing engine bug and its whole bug class, makes failed duels recoverable, moves deck ownership into the story save under a real invariant, and rebuilds the app's front door around the visual novel with an explicit Free Play mode.

Scope

In — duel field fixes 1–10 · engine response-encoder contract + audit · replay-based duel recovery · save-owned decks + free-play library split · card-ownership invariant · collection screen · shell main menu + free-play mode + route contexts · set-image acquisition pipeline · shop grid/art/sort · booster reveal rework + zoom inspector · story choice list + danger styling · AGENTS.md trunk rewrite.

Out — multiplayer · deck sharing beyond YDK · banlist editing · a card database richer than the collection screen · opponent AI work beyond deck selection · new story content · canvas field · ADR-024 portrait work · engine vendor upgrade · ownership gating in free play.

Assumptions

  • The deck-editor round-2 work is already merged into main and the three worktrees are already removed. Every ticket runs on main.
  • ADR-022's import boundaries survive untouched; only its branch/worktree topology is retired (ADR-045).
  • “Maximum copies” in free play governs ownership; the pinned ruleset still caps deck copies.
  • #/duel and #/decks redirect to their free-play homes so old bookmarks and the PWA start URL keep working.
  • Per-domain chunk budgets are re-measured where the restructure moves code; build:verify stays green.

Working rules

  • TDD per ticket. Red test named in the ticket, then the minimum code, then refactor while green.
  • Every ticket is self-contained. A worker reads one file: goal, scope fence, what its predecessors produced, exact paths and symbols, exact commands.
  • The app compiles and runs after every ticket. Each one is a commit-sized slice with its own validation list.
  • Gates: npm run check:headless per ticket; npm run build && npm run build:verify where chunks move; npm run test:e2e for handoff-touching work.
  • Contracts: data-cy on every rendered element, public-entry imports only, and a deliberate edit to tests/unit/domain-boundaries.test.ts whenever a public API widens.
