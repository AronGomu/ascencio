# Explanation from reviewer C for prospective refinement execution

## 1. Outcome and scope

I would produce a complete, shorter sibling skill package from a required source folder, preserving its intended outcome, essential behavior, dependencies, deterministic outputs and specified formats. Optional inputs set priorities, retained requirements, iteration count, destination and review context. Success requires completing the requested iterations, resolving reviewer misunderstandings, validating affected contracts, and reporting evidence without promoting the candidate. This document describes execution only; it does not perform refinement.

## 2. Process overview

As orchestrator, I would read the package and applicable authoring guidance, inventory its behavioral baseline, and explain the incoming skill. Each iteration simplifies the candidate, audits preservation, validates relevant changes and obtains three independent comprehension explanations. I would compare normalized behavior, repair actual disagreements and repeat validation and fresh review until misunderstandings are resolved. Completed iterations feed one external report and final delivery.
