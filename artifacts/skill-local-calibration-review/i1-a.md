# Explanation from review_i1a for local-calibration skill execution

## 1. Outcome and scope

Improve a required target `ai-bot` through reproducible paired game evaluation against frozen opponents, always including its starting AI, and deliver the accepted committed source, verified comparison results and compact attempt history. Optional inputs are extra opponents, owner limits and a compatible checkpoint. Only target AI changes are allowed; decks, engine, legality and hidden-information boundaries remain protected. Success can be an honestly unchanged accepted source when no candidate qualifies. This explanation reads only the specified skill package and explanation template; it does not execute a campaign or inspect gameplay.

## 2. Process overview

Prepare frozen identities, budgets, starting archive and both local concurrency recommendations; evaluate baseline, record its accepted reference and analyze its target losses. Subsequently replay isolated corrections against the selected analysis source, assemble passing corrections, evaluate the combined candidate against accepted control, decide strictly on paired improvement, commit every evaluated candidate and analyze even rejected or final evaluations. Pending reasons accumulate across iterations. No qualifying correction or the decision ceiling leads to delivery; resource and stop incidents suspend through verified checkpoints. The stage dispatcher is stateless: owning project tools persist work and the orchestrator verifies semantic gates.
