# Explanation from reviewer 3 for refined skill comprehension

## 1. Outcome and scope
Improve one required target ai-bot against frozen opponents, always including its starting AI; optional opponents, owner limits and compatible checkpoint complete inputs. Change target AI only. Success delivers verified accepted source, results and history; honest unchanged or incomplete outcomes remain valid reports. YAML permits implicit invocation.

## 2. Process overview
Prepare → Evaluate → Decide → Analyze → Replay → Assemble loops into Evaluate. Analyze delivers at the decision ceiling; Replay delivers without qualifying edits. Any active stage may suspend. Orchestrator implements; analysts diagnose only.

## 3. Execution matrix

| Step | Entry condition | Action and owner | Concurrency | Decision/completion criterion | Saved output | Next step |
|---|---|---|---|---|---|---|
| Prepare | Inputs resolved | Orchestrator freezes setup, archives start, calibrates | Separate pools; no evaluation/analysis overlap | Verified setup and matching recommendations | Configuration, schedule, slice plan | Evaluate |
| Evaluate | Baseline/candidate frozen | Owning tools reuse compatible evidence/run remainder | Optimal match workers; four games sequential | All matches finalized, reservations settled, coverage verified | Results, paired difference | Decide |
| Decide | Evaluation complete | Orchestrator verifies and persists decision; archives evaluated candidates | One task | Baseline sets accepted; candidates require strict valid improvement | Commit, history, checkpoint | Analyze |
| Analyze | Decision recorded | Slice owners inspect all completed target losses; orchestrator merges | One owner/250-match slice, queued slots | Exactly-once coverage; global reasons ≥5 losses | Bound Markdown report | Replay/Deliver |
| Replay | Eligible reasons/history checked | Orchestrator tests isolated variants | Measured replay workers | All cases settle; ≥5 AND ≥5% convert into wins with changed intended choice | Hashes, controls, takeovers | Assemble/Deliver |
| Assemble | Passing edits | Orchestrator combines, validates/freezes | One task | Preserve validated semantics; changed isolated logic re-gated | Candidate, attributed history | Evaluate |
| Deliver | Ceiling/no edit | Verify, rank existing comparisons, export, consolidate | One task | Checked report before eligible cleanup | Accepted export/hash, report | Closed |
| Suspended | Incident/stop | Shutdown, settle, checkpoint/report | Owned work only | Verified shutdown | Prior stage, budgets, pending work | Authorized resume |

## 4. Identities and invariants

| Item | Initial source/value | Allowed changes | Must remain fixed | Verification |
|---|---|---|---|---|
| Sources | Starting/accepted commits | Ordinary: one addition from accepted; regression: remove/update one rule from regressing candidate | Frozen opponents; unedited repair rules | Separate accepted, analysis/replay and assembly identities |
| Comparison | Pinned schedule/identities | Accepted advances only on promotion | Seeds, starting orders/sides, rules/content, implementations | Paired intersections; every opponent represented; equal opponent weights; draws zero wins; symmetric ignores |
| Evidence | Typed lossless logs | Matching cache reuse | Exact IDs/hashes, visibility boundaries | Analysts receive positive allowlisted target-loss projections only |
| Calibration | Matching machine/workload identities | Recalibrate mismatches | Required repetitions/outcomes | Counts 2…logical CPUs; replay two repetitions, smallest within 3% fastest median |

## 5. Limits and accounting

| Resource/stage | Default limit | Override rule | Accounting | Action at exhaustion |
|---|---|---|---|---|
| Decisions/evaluation | 50; 2,500 four-game matches | Pin effective owner values | Baseline excluded; floor/remainder allocation; planned=(1+decisions)×matches×4; recovery=floor(10%) | Ceiling after analysis; recovery exhaustion ignores remainder |
| Time/storage | 24h; 50GB; 16MB control reserve | Explicit resolved configuration | Original start includes downtime; logical/import bytes; reservations/failures count, cache free | Suspend |
| Deadlines | Evaluation 5h; preparation 10m; validation/replay-prefix 5m; shutdown 1m | Effective values capped by remaining time | Launch-to-exit; diagnostics separate, time/storage charged | Incident policy |

## 6. Incidents and continuation

|---|---|---|---|---|

| Calibration/build format | Retain failure; fresh directory | Calibration once/count; tooling-only adaptation before admission | Both attempts | Qualifier/valid package |
