# Explanation from reviewer B for authoring execution comprehension

## 1. Outcome and scope

I would create or revise an agent skill matching the user's requested behavior, with clear invocation, explicit model defaults, actionable instructions and preserved useful existing requirements. Required context is the requested task and destination or existing package; I would infer routine details and ask only for missing decisions that block intent or essentials. Completion includes a separate five-iteration refinement review and its evidence, while the authored package remains the delivered source. This document describes execution only.

## 2. Process overview

I would read the complete applicable guidance, establish behavior before drafting, adapt the annotated template, and verify the resulting package. Earlier guideline rows resolve authoring-rule conflicts; higher-level instructions and explicit user decisions govern first. After each completed authoring task, I would delegate one automatic review per changed skill. That review builds a separate candidate, repeatedly simplifies, verifies and obtains fresh comprehension explanations, then reports evidence without promoting its result. Dependency links require reading, not recursive execution.
