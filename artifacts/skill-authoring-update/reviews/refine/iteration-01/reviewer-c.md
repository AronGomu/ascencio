# Explanation from reviewer C for prospective refinement execution

## 1. Outcome and scope

Given a skill folder, I would produce a complete, readable sibling candidate that preserves the source's intent, essential behavior, deterministic outputs and required structure. Optional inputs set priorities, retained requirements, iteration count, destination and review context. Success means completing the requested simplification iterations, resolving comprehension misunderstandings, retaining independent preservation evidence and delivering the candidate with explanations, reviews and one concise external report. This document explains execution; it performs no refinement.

## 2. Process overview

I would inventory the incoming package before changing wording, explain its current execution, then simplify the separate candidate. Each iteration contains a verification and fresh comprehension-review loop; corrections return to verification until reviewers have no remaining behavioral misunderstandings. After recording that iteration's accounting and evidence, I would repeat simplification for the requested count. Authoring dependencies apply throughout, but their mutual refinement links do not launch nested automatic reviews.
