# Explanation from reviewer A for candidate comprehension

## 1. Outcome and scope

Produce a complete, readable sibling skill package with less unnecessary instruction while preserving the supplied skill's intent, dependencies, essential behavior and output contracts. A skill-folder path is required; priorities, retained requirements, iteration count, destination and review context are optional. Success requires completing the requested iterations, resolving comprehension disagreements, preserving the source, and delivering the candidate with external evidence and a concise report. This document explains execution; it does not perform refinement.

## 2. Process overview

The orchestrator first reads the package and inherited authoring guidance, inventories its behavior, and explains the incoming skill. Each outer iteration simplifies the candidate, then enters a verification/comprehension loop. Relevant checks precede three fresh independent explanations; behavioral disagreement triggers minimal corrections and another check/review pass. Only agreement completes that iteration. The outer loop repeats simplification for the requested count, then delivers evidence without promoting the candidate. Circular authoring/refinement links provide dependencies rather than recursive launches.
