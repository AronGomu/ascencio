# Explanation from reviewer-a for prospective refinement execution

## 1. Outcome and scope

I would produce a complete, simpler sibling skill package from a supplied skill folder, preserving its intent, essential behavior, deterministic outputs and specified formats. Optional priorities, retained requirements, iteration count, candidate destination and review context constrain the work. Success requires completing the requested iterations, resolving reviewer misunderstandings, retaining the source unchanged, and delivering candidate links with evidence and honest accounting. This document explains that execution without performing it.

## 2. Process overview

I would first read the package and its authoring dependencies, inventory behavior, and explain the incoming skill. Each iteration would simplify the candidate, verify relevant changes, obtain three fresh comprehension explanations, compare them against source steps and matrix items, and minimally correct misunderstandings. Verification and fresh review repeat until misunderstandings disappear; the next outer iteration resumes simplification. Automatic authoring review remains one review context throughout.
