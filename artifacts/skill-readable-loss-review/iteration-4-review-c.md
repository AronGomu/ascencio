# Explanation from fresh reviewer C for readable-loss skill execution

## 1. Outcome and scope

Improve the target AI against frozen opponents, including starting self-opponent. Deliver accepted source, verified comparisons and history; unchanged acceptance is legitimate. Protect decks, engine, legality and information boundaries. External contracts remain execution prerequisites.

## 2. Process overview

Prepare identities, limits, policy and calibration; evaluate, decide, analyze, replay, assemble and repeat. Analyze every evaluated candidate, including final rejection. Strict paired improvement promotes. No qualifying edit ends normally; exhaustion suspends. Controller checks edges; owning tools persist state; orchestrator verifies semantic gates.

## 6. Incidents and continuation

| Incident | Immediate action | Retry allowance | Evidence preserved | Resume condition |
|---|---|---|---|---|
| Individual timeout | Bug report; finalize ignored, never conversion | None | Reasons; paired exclusion | Continue safe jobs; replay denominator retains timeout |
| Calibration failure | Preserve attempt, fresh directory | One retry then exclude count | Attempts, measurements, exclusions | Same pinned identity; no qualifying count stops preparation |
| Integrity/initialization/sideboarding failure | Stop unsafe execution | No generic retry | Diagnostics and bindings | Resolved cause; owner if unresolved |
| Resource or owner stop | Stop admission/owned work, settle reservations | Explicit continuation | Claims, uncovered losses, budgets/checkpoint | Verified checkpoint plus applicable authorization |

Shutdown allows 60 seconds before terminating owned process groups. Unsupported packages permit tooling-only adaptation and fresh uncharged validation. Analyst failure preserves uncovered work.
