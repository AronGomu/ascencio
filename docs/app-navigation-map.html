Why it changed

  • Two menus in a row. The shell home listed Story · Decks · Duel; picking Story showed the visual novel's own title screen with the real entries. The second menu was the game's front door.
  • "Decks" became ambiguous. With save-owned decks (ADR-049) a deck list is either a save's or the free-play library's. One #/decks route cannot say which, and a bookmark would mean whichever mode you were last in.
  • The story must stay lazy. domain-loaders.ts imports each domain on demand and build:verify enforces DOMAIN_BUDGET_BYTES. Putting the story's title at the app root would drag the whole visual novel into first paint — so the menu moves into the shell instead.

Settings is a dialog from any menu, never a route. A story-scoped route with no save loaded returns to #/ instead of rendering empty. Either collection is reached from the deck editor's own menu, in the world that editor was opened for, and ships as a chunk of its own behind the story entry — the narrative routes never pay for it.

New Game, Continue and Load navigate to #/story carrying which entry was pressed. The story reads that intent once at mount and applies it after storage has answered, out of its own title screen only, so the second menu ADR-051 exists to remove cannot come back; leaving #/story drops the intent. Going the other way is reported rather than linked: the story asks for #/story/decks, writes the run to the autosave slot, and only a write that landed hands the route to the shell — a route change unmounts the visual novel with everything it has not written (acbb212).

The deck editor is a single screen. What differs is the DeckEditorContext the shell builds per route.

The story column is built in one place: openStoryDeckContext reads the save once and returns the repository, the ownership and the banner name together. It is also all src/story/index.ts exports of that pairing — neither createStoryDeckRepository nor storyCardOwnership leaves the domain on its own (acbb212), so a story repository paired with free play's unlimited ownership is unrepresentable, which is what T23 exists for.

What stayed put

  • ADR-022 import boundaries: public entries only, enforced by eslint.config.js and tests/unit/domain-boundaries.test.ts.
  • Lazy domain loading and per-domain byte budgets (build:verify).
  • The duel handoff vocabulary — the story still never mounts a duel, and the shell still settles exactly one result.
  • The data-cy contract on every rendered element.
