# Explanation from review A for fresh comprehension

## 1. Outcome and scope

Improve one supplied target AI against frozen opponents, including its starting self, through reproducible paired evaluation. Deliver the accepted source, verified results and compact history, honestly retaining unchanged source when nothing qualifies. Only target AI changes; decks, engine, legality and information boundaries remain protected. Use current session-typescript/v1 tools; incompatible legacy checkpoints require fresh runs.

## 2. Process overview

The orchestrator implements; delegated analysts diagnose losses. A stateless controller exposes stages while project tools persist execution and checkpoints. Baseline and every evaluated candidate pass Evaluate → Decide → Analyze. Authorized replay validates isolated edits, assembly combines passing edits, and evaluation alone establishes promotion. Pending rules accumulate across iterations without granting additional iterations or resources. Stops supersede normal transitions.

## 4. Identities and invariants

| Item | Initial source/value | Allowed changes | Must remain fixed | Verification |
|---|---|---|---|---|
| Sources | Frozen starting self/opponents; moving accepted reference | Ordinary: add isolated fix to accepted source. Valid regression: remove/update one rule on regressing candidate, add none | Promotion comparator remains accepted; baseline has no removal analysis | Commit/hash and separate accepted, analysis/replay and assembly identities |
| Pairing | Pinned schedule, inputs, seeds, sides, content/runtime | Trajectories may diverge | Starting inputs, opponent order, deterministic IDs | Paired completed intersections; either ignore excludes both sides |
| Score | Game wins/nonignored completions | Accepted changes on strict improvement | Draws count denominator; equal opponent weights; every opponent paired; no confidence intervals | Integrity/comparability gates |
| Pending rule | Stable reason/rule IDs, aliases, semantic hash | Explicit reconciliation; materially different correction gets new ID | Provenance, original logs/decisions/choices; ≤300 distinct first-seen losses | Fresh current-analysis-source control and plus-rule replay of old/new cases; never force historical choices |

## 5. Limits and accounting

| Resource/stage | Default limit | Override rule | Accounting | Action at exhaustion |
|---|---|---|---|---|
| Decisions/evaluation | 50 decisions; 250 four-game matches | Pin owner limits | Baseline excluded from decisions; floor allocation/remainder by frozen opponents | Analyze final decision, then deliver |
| Games | (1 + effective decisions) × matches × 4; recovery floor 10% | Pinned configuration | Failed/interrupted reservations count; cache zero; diagnostics separate | Recovery exhausted: ignore remaining interrupted games |
| Time/storage | 24h; 50GB, protected 16MB control reserve | Explicit continuation, complete effective limits | Original start includes downtime; logical/import bytes; locked reservations | Suspend, block data writes |
| Deadlines | Evaluation 5h; preparation 10m; validation/replay branch 5m; shutdown 60s | Resolved configuration, remaining-wall cap | Replay includes prefix; all diagnostics consume resources | Incident policy |
| Calibration | Counts 2…logical CPUs | Recorded permitted exclusions | Required successful repetitions; replay two, smallest within 3% fastest median | No qualifying count stops Prepare |

## 6. Incidents and continuation

| Incident | Immediate action | Retry allowance | Evidence preserved | Resume condition |
|---|---|---|---|---|
| Individual timeout | Bug report; finalized ignored result, never conversion | None | Outcome/reason | Continue safe jobs |
| Interrupted evaluation | Recover missing work | Within recovery allowance | Attempts/reservations/completions | Remaining resources |
| Calibration stage failure | Fresh evidence directory | Once; second failure excludes count | Both attempts/exclusions | Other counts continue |
| Unsupported package preadmission | Adapt tooling only; local checks/fresh validation | No game charge | Failed validation | Valid protected boundaries |
| Integrity/initialization/sideboarding/non-timeout failure | Stop; resolve integrity first | No generic replay retry | Diagnostics/checkpoint | Resolve; ask if unresolved |
| Exhaustion/pause/cancel/analyst failure | Stop admission, bounded owned shutdown, settle/checkpoint | No implicit increase | Claims, uncovered losses, prior stage/budgets | Explicit authorized continuation |
