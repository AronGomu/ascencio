# Explanation from review_i1b for local calibration skill execution

## 1. Outcome and scope

The workflow seeks a higher paired-game win rate for one supplied `ai-bot`, delivering accepted source, verified results and compact attempt history; an honest unchanged result also completes it when no correction qualifies. Optional inputs are extra opponents, owner limits and a compatible checkpoint. Only target AI may change. This explanation is based exclusively on the supplied local-calibration skill package and explanation template; it describes execution without running the workflow, inspecting gameplay or reading external project contracts.

## 2. Process overview

Prepare freezes configuration, sources, opponents, schedule and separate local match/replay worker recommendations. Evaluate baseline or assembled candidate, Decide against accepted control, then always Analyze that evaluated source. Analysis selects accepted-source improvement or regressing-source repair; Replay tests isolated rules and accumulated pending cases against the selected current source. Passing rules assemble into another evaluation; no passing rule or the analyzed decision ceiling leads to delivery. Resource and stop incidents interrupt this loop into a verified suspended checkpoint. The stateless controller checks stage edges; project tools own persistence, admission and publication, while the orchestrator verifies semantic gates and implements changes, delegating diagnosis only.

## 4. Identities and invariants

| Item | Initial source/value | Allowed changes | Must remain fixed | Verification |
|---|---|---|---|---|
| Opponents and comparison | Frozen opponents always include starting AI; moving accepted control separate | Accepted source changes only on promotion | Opponents, order, paired inputs, seeds, sides, rules/content and schedule | Exact hashes/configuration, stable match/game randomness and paired coverage |
| Ordinary source mode | Baseline, acceptance, tie or unassessable rejection | Add one fix per isolated variant | Analysis, unchanged replay control and assembly base all use accepted source | Still analyze rejected evaluation before returning to retained accepted analysis |
| Regression repair | Valid lower paired candidate rate | Remove/update one existing rule, add none | Regressing candidate is analysis/replay/base; unedited rules preserved; promotion comparator remains accepted | Paired metadata flags new losses; analysts inspect candidate losses only; implicated rules ranked by distinct supported losses, without causal claims |
| Promotion | Game wins/completed non-ignored games; draws zero wins in denominator | Strictly greater equal-opponent-weighted candidate rate can promote | Completed paired intersections exclude either-side ignores from both sides; every opponent requires a completed pair | Unresolved/mismatched comparison unassessable; no confidence intervals or match-weighted promotion |
| Rule eligibility and validation | Supported reasons include singleton and sub-five groups in ledger | Replay-eligible at five distinct associated losses globally; validate at least five converted wins AND at least 5% of denominator with intended choice changed | All associated cases replay at recorded primary critical decision against unchanged analysis source; unchanged/nonwinning choices are nonconversions | Ignored replay timeouts settle, stay in denominator, never convert |
| Pending rule identity | Stable reason ID/aliases, exact semantic rule/source hash and original case provenance | Explicit reconciliation may merge similar reasons; materially different correction gets new rule identity | Distinct corrections remain separate; historical outcomes never replace current-source outcomes | Replay all accumulated original-input cases under current source; avoid silently forcing historical policy prefixes |
| Pending disposition | First-seen stack, max 300 distinct losses per reason/rule | Below either threshold remains pending below cap; complete valid current-source failure at 300 proves exact rule discarded | Repeated executions add no cases; interruptions/resources/integrity cannot prove discard | Archive denominator/counts/source/rule/evidence; unchanged discarded rule excluded later |
| Completed calibration reuse | `.cache/typescript-native-workers.json` and `.cache/replay-workers.json` | Recalibrate on missing/unreadable/unusable count or owner request | Local paths are reuse keys; source, bot, fixture, skill, runner/runtime/version changes and missing old evidence manifests do not invalidate usable saved counts | Count is integer, positive, within available logical CPUs; identities/measurements are provenance only |
| Unfinished calibration | Official output directory and attempts.json | Resume only exact compatible identity; ordinary failed stage has one fresh-directory retry | Both attempts, exclusions and retained measurements persist; revalidate unfinished evidence | Unlike completed recommendation reuse, unfinished stage continuation requires exact identity |
| Source archive | Exact initial source commit on main or matching existing commit | Commit each fully evaluated candidate, accepted or rejected; temporary variants content-hashed only | Accepted independent of HEAD; immutable run/version IDs, required trailers, full SHA/path/hash | Recover helper journal; retrieve committed package/source explicitly; only intended bot/history files committed |
