# ADR-092: Immutable per-file release delivery replaces player ZIPs

> Status: accepted; implemented
> Decided: 2026-09-13
> Owners: content producer / release infrastructure
> Amends: ADR-075 D1,D3–D4; ADR-080 D1–D2; ADR-082 D2,D5–D7 for player releases only
> Implemented: `5c2ddff95fe224276d5f72f746c3458fe26a0f30` (T4 producer/publisher) and `8a0d513b185addec82ff1b103d6a27287768d3bd` (T5 verified staging/resume/cache).
> Baseline: `010401956d0cd59d8e6dda91bd367040f5de669e` — inspected pre-implementation source.

## Context

Existing player producer already emits sorted logical path, byte length, SHA-256 before ZIP packaging. ZIP identity changes across unrelated file updates. Full content inventory may contain 50,000 entries; embedding inventory in CORE couples executable updates to media. Source: scripts/lib/asset-delivery/player-payload.ts; scripts/lib/asset-delivery/player-bundle.ts at baseline 010401956d.

## Decision

D1. Player delivery uses independent immutable files identified by canonical logical path plus full producer-computed lowercase SHA-256 version and byte length. No player ZIP bridge; no deployed ZIP installations require one. Developer archive tooling remains separate.

D2. Full canonical manifest is remote. CORE holds delivery base/stable latest pointer plus compatibility epoch, not asset inventory. Manifest records explicit required role and chapter ownership. A bounded 50,000-entry manifest is supported without raising frozen runtime-specific parser limits.

D3. R2 Standard custom HTTPS hosts immutable file objects, then immutable manifest; publisher conditionally changes latest pointer last only after closure verification. Existing objects never overwrite divergent bytes. Monotonic release sequence plus pointer CAS prevents stale concurrent publication.

D4. Canonical source bytes and derived metadata determine generated bytes. CI rehashes current sources and rejects stale candidates, not merely internally consistent frozen output. Producer validates semantic release continuity through domain public validators before official pointer publication.

D5. No signed-manifest trust system or historical executable-version selector. Full integrity digests remain required. Historical release objects stay immutable; remote prune/deployment are outside this change. Rights eligibility, explicit operator approval, no secret exposure remain mandatory.

## Consequences

C1. Unchanged file versions reuse storage/downloads across releases; required metadata activates without bulk media.

C2. More requests and larger remote manifest; publisher needs conditional-write/concurrency tests. Immutable storage grows; no automatic cleanup offsets it. Local fake-R2 tests do not prove live hosting.

## Alternatives rejected

A1. Player ZIP parts: coarse update/resume granularity.

A2. CORE-embedded inventory: executable/content release coupling.

A3. Mutable file paths: stale caches and mixed releases.

A4. Short digest: requires collision policy; existing full SHA-256 is sufficient.
