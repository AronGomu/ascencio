# Explanation from reviewer A for candidate comprehension

## 1. Outcome and scope

Improve one required `ai-bot` against frozen opponents, including its starting self, using reproducible paired games. Optional inputs are additional opponents, owner limits and a compatible checkpoint. Success delivers the retained accepted source, verified comparisons and compact attempt history; unchanged completion is valid when nothing qualifies. Only target AI changes; decks, engine, legality and information boundaries remain protected. This explanation describes the candidate package without executing it.

## 2. Process overview

A stateless controller prints inherited policy and one stage, checking legal transition names while project tools persist execution. Prepare establishes identities and calibration; Evaluate and Decide establish baseline or judge a candidate; Analyze always follows, including the last decision. Replay tests isolated hypotheses, Assemble combines passing edits, and evaluation repeats. A decision ceiling or no qualifying edit leads to delivery; incidents can suspend any active stage. The orchestrator verifies semantic gates and implements edits, delegating only loss diagnosis.
