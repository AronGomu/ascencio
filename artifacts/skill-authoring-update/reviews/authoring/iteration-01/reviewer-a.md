# Explanation from reviewer A for authoring candidate comprehension

## 1. Outcome and scope

Create or revise an agent skill from the user's intended outcome, inputs, constraints and delivery needs. Success means a usable package following the applicable template, preserving useful existing instructions and requested scope, with explicit model defaults and a separately saved automatic refinement candidate. The authored package and review candidate are distinct deliverables; completion never implies promotion. This explanation describes execution only.

## 2. Process overview

Read the candidate's ordered guidelines and supporting writing guidance, infer requirements, and author a task-appropriate skill. Verify it, then delegate one five-iteration refinement review per changed skill. That child inventories behavior, explains, simplifies, checks, obtains three fresh comprehension explanations, repairs misunderstandings, and repeats. Review-generated edits stay inside that review rather than launching recursive authoring reviews. Deliver both authored results and review evidence.

## 5. Limits and accounting

| Resource/stage | Default limit | Override rule | Accounting | Action at exhaustion |
|---|---|---|---|---|
| Automatic review | Five iterations per changed skill | Explicit session instructions govern | Per-iteration counts/findings/checks | Deliver review evidence |
| Comprehension | Three fresh reviewers per review round | Required settings unavailable means pending | Keep explanations separate | Repair and repeat until understood |
| Compression | Aspirational 25% reduction | Preservation/readability take precedence | Count all agent-facing prose, references/configuration and generated copies | Continue useful simplification; never encode for size |
| Package size | No fixed quota | None prescribed | Report physical size separately; exclude executable-only source, inputs and review artifacts from instruction counts | No invented stopping quota |
