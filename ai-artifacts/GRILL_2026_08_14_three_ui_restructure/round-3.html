1. Integration order for the unmerged duel-field branch

31 finished commits rewrite src/styles/app.css, vite.config.ts and the build verifier. Restructuring before they land guarantees a brutal merge.

2. What happens to the stale VN and DECKBUILDER branches?

Both point at 7ae8011, an ancestor of plan/feedback-follow-up. Their worktrees are where parallel UI work would otherwise start.

3. Resolve 16:9 letterbox versus mobile portrait

You asked for a global 16:9 stage with black bars and mobile vertical design below Full HD. Both rules claim every window under 1920px.

4. Which domains must work in portrait?

Portrait duel is the expensive one: the field geometry, hand band and phase strip are all built around a wide board.

5. Admin surface shape

You want a hidden testing page behind /admin. The app is a static hash-routed SPA, so a real path needs server rewrites; a hash route needs none.

6. What does the admin page contain?

Round 2 deletes the VN review drawer and deck fixture switcher; the admin page is where that capability can survive if you want it.

7. Which deck does the story opponent use? (unanswered in round 2)

Main already ships six bundled decks and a pre-duel deck picker; encounters still need to declare their opponent.

8. Fullscreen restore behavior on return

You want the toggle remembered so returning players land in fullscreen. Browsers reject requestFullscreen() without a fresh user gesture, so a stored true cannot auto-apply on load.

9. Scope of the CSS design-system extraction

"Design system first" can mean a token file, or a full visual redesign of three UIs that currently look nothing alike.

10. Which build gates stay active while JS budgets are suspended?

The verifier also enforces engine-chunk shape, Node/engine marker bans, licenses, image coverage, snapshot identity and Worker digest — independent of size budgets.
