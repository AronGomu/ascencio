# Explanation from reviewer C for prospective refinement execution

## 1. Outcome and scope

I would produce a complete, readable sibling refinement of a supplied skill folder, preserving its intent, essential behavior, deterministic outputs and specified formats. Optional inputs set priorities, iteration count, candidate destination and review context. Success requires the requested iterations, comprehension convergence and an evidence-backed report; promotion remains outside this process. This document describes execution without performing it.

## 2. Process overview

The orchestrator first establishes the incoming contract, then simplifies a separate candidate. Each iteration includes checks, independent deletion and boundary audits, and three fresh comprehension reviews. Misunderstandings trigger minimal corrections followed by another checks-and-review cycle. Once explanations agree behaviorally, record the iteration and repeat simplification until the requested count is complete. Linked authoring requirements apply throughout; their mutual refinement link does not start recursive reviews.
