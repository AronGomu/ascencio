The invariant

Every card in a story deck is a card that save owns.

Everything below exists to state that once and enforce it in the four places it can be broken or discovered. Free play short-circuits all of it with a single flag.

Where data lives

The ownership contract

interface CardOwnership {
  ownedCount(code: number): number;
  readonly isUnlimited: boolean;
}

storyCardOwnership(state)   // collection[code] ?? 0
unlimitedCardOwnership()    // Infinity, isUnlimited: true — a flag, never a stored record

Free play is not a materialised collection of every card times three. It is one branch in one function: nothing to write, nothing to migrate when the card pool grows.

Ownership governs availability, not legality. The pinned ruleset still caps copies, so what you can add is min(ownedCount, rulesetLimit).

Four enforcement points

CatalogT24Story lists only owned codes; add is capped by owned × ruleset, across all three zones.

Sell screenT26Selling stays free, but a sale that breaks decks names them in a dialog before it commits.

How the invariant can break — and what happens

New-save grant

  • Starter deck: the existing src/battle/duel/presets/decks/player.ydk, built through the normal deck model so its validation summary is real.
  • Its cards are credited to the collection at the counts the deck uses, rarity common for the sell ladder.
  • Wallet unchanged at 1000 DP; a pack costs 150 DP.
  • Deterministic: fixed id and timestamps, so two new games produce identical decks and collections and a test can diff them.

Consequence: the opening encounter is playable immediately, and everything in your deck is something you own — the invariant holds from turn one.

Collection screen

  • Same grid and tile proportions as the set card list; shared CardPreviewPanel from the shell, not the new zoom inspector.
  • Story: owned cards with counts. “Show every existing card” is unchecked by default and reveals unowned cards dimmed.
  • Free play: the whole database, no counts — every card is available anyway.
  • Tri-state rarity grouping shared with the set list and the pack results screen.
  • Reached from the deck menu in both contexts; the show-all checkbox lives here and not in the builder's catalog.

Explicitly later: filters, search, and the full database interface. This screen is the browse surface those will grow from.
