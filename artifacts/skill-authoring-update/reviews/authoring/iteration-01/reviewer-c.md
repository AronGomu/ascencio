# Explanation from reviewer C for authoring candidate comprehension

## 1. Outcome and scope

Create or revise an agent skill from the user's intended outcome and available requirements, using the annotated template selectively. Success means a usable authored package with placeholders/comments removed, useful existing instructions and scope preserved, explicit model defaults, and a separately saved five-iteration refinement candidate with evidence. Reviewing that candidate never authorizes replacing the authored source. Required input is sufficient task intent; missing information is requested only when it cannot safely be inferred.

## 2. Process overview

Read the entire candidate and ordered guidelines, then supporting writing guidance and skill mechanics. Inventory behavior before drafting, organize the appropriate template sections, and verify the resulting package. Each completed authoring task triggers one refinement child per changed skill. The child reads dependencies without recursively launching authoring review, inventories and explains its source, simplifies a separate copy, checks it, and repeats fresh three-reader comprehension review/correction before recording each iteration. Deliver source and candidate evidence separately.

| Item | Initial source/value | Allowed changes | Must remain fixed | Verification |
|---|---|---|---|---|
| Behavior | Existing skill and user scope | Explicitly authorized requirements | Contracts, ownership, gates, failure distinctions | Inventory, deletion audit, boundary scenarios |
| Rule priority | Ordered guideline rows | Higher authority/user decisions | Earlier rows win ties/conflicts | Conflict evaluation |
| Authored source | Completed authoring package | Later separate promotion only | Read-only during review | Source identity comparison |
| Candidate | Complete sibling package | Review edits | Existing candidates preserved | Unique destination and reference checks |

## 5. Limits and accounting

| Resource/stage | Default limit | Override rule | Accounting | Action at exhaustion |
|---|---|---|---|---|
| Models | GPT-6.1 Sol, low thinking | User choice or documented task override | Actual settings and unsupported controls | Report unavailable settings honestly |
| Automatic review | Five iterations; three fresh readers per review | Session instructions govern | Per-iteration counts/findings/checks | Deliver on completion; unresolved work disclosed |
| Compression | Aspirational 25% | Readability and preservation prevail | All instructional references/configuration/copies; physical size separately | Continue useful simplification without forced density |
| Retries | No numeric general cap | Only meaningful cost/risk warrants one | Do not invent quotas | Clarify blocking policy ambiguity |
