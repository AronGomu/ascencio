# Explanation from r2c for fresh comprehension review

## 1. Outcome and scope

Improve one supplied target bot against frozen opponents, always including its starting AI, while preserving decks, engine, legality and information boundaries. Deliver accepted source, verified paired results and compact history; unchanged acceptance is successful honest completion when no edit qualifies. Optional opponents, owner limits and compatible checkpoints refine the run.

## 2. Process overview

Prepare pins identities, limits and separate calibrations. Evaluate baseline or assembled candidate; Decide persists results; Analyze always follows, including final/rejected evaluations. Authorized Replay tests isolated rules, then Assemble combines passing rules and returns to evaluation. No passing rule or decision ceiling leads to delivery; stops supersede every edge. The controller is stateless: project tools own execution/persistence, while the orchestrator verifies semantic gates and implements changes, delegating diagnosis only.

## 4. Identities and invariants

| Item | Initial source/value | Allowed changes | Must remain fixed | Verification |
|---|---|---|---|---|
| Evaluation | Pinned starting inputs | Accepted comparator moves | Opponents, schedule, implementation identities | Hashes, receipts, paired intersections; every opponent paired |
| Score | Game wins/completed nonignored games | Candidate outcomes | Draws zero wins; equal opponent weights | Exclude either-side ignores from both; no confidence intervals |
| Ordinary mode | Accepted source | Add one fix per variant | Analysis/control/assembly all accepted | Source-bound analysis; rejected evaluation still analyzed |
| Repair mode | Valid regressing candidate | Remove/update one existing rule, add none | Unedited candidate rules; accepted comparator | New-loss metadata, candidate losses only |
| Pending rule | Stable reason/rule IDs, semantic hash | Explicit aliases/reconciliation; materially different correction gets new ID | Original provenance and failed history | Distinct first-seen losses, maximum 300; no repeat-execution cases |
| Replay stacks | Original inputs/decision IDs | Fresh current-source control plus rule each iteration | No silently forced historical policy prefix | Reconstruction, legality, applicability; incompatible modes blocked |

## 5. Limits and accounting

| Resource/stage | Default limit | Override rule | Accounting | Action at exhaustion |
|---|---|---|---|---|
| Decisions/evaluation | 50; 250 four-game matches | Pin owner limits | Baseline excluded; equal allocation plus ordered remainder | Final analysis then deliver |
| Games | Planned=(1+decisions)×matches×4; recovery=floor(10%) | Pinned setup | Attempts/reservations count; caches none | Interrupted remainder ignored after recovery exhausted |
| Time/storage | 24h; 50GB | Explicit continuation, full effective limits | Original start includes downtime; logical bytes/imports; 16MB protected reserve | Suspend; no further analysis/export/cleanup |
| Deadlines | Evaluation 5h; preparation 10m; validation/replay 5m; shutdown 60s | Effective pinned values | Launch-to-exit including replay prefix, wall-time capped | Incident policy |
| Replay/calibration | No replay game quota | No implicit extra budgets | Separate diagnostics/control/takeovers; all time/storage | Pending never authorizes extension |

## 6. Incidents and continuation

| Incident | Immediate action | Retry allowance | Evidence preserved | Resume condition |
|---|---|---|---|---|
| Individual timeout | Bug report, ignored denominator/nonconversion | Never case retry | Outcome/reason | Other safe jobs continue |
| Interrupted evaluation | Recover missing work | Within recovery allowance | Verified completions/all attempts | Remaining deadlines/resources |
| Calibration failure | Fresh directory, same inputs | Once per failed stage; then exclude count | Both attempts/exclusions | Qualifying optimum across counts 2..CPUs; otherwise stop |
| Integrity/initialization/sideboarding/non-timeout | Stop, never ignore unsafe state | No generic retry | Diagnostics/checkpoint | Resolve; ask if unresolved |
| Resource/owner/analyst stop | Stop admission, bounded owned shutdown, settle/checkpoint | Explicit continuation | Claims/uncovered losses/budgets | Verified same checkpoint and applicable authorization |
| Unreconstructable pending case | Block rule | No fabricated rejection | Diagnostics/provenance | Exact current-source reconstruction |

|---|---|---|---|---|
