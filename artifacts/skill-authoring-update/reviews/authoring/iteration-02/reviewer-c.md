# Explanation from reviewer C for prospective skill authoring

## 1. Outcome and scope

I would create or revise a skill from its requested purpose and available source package, producing usable instructions with an explicit model-defaults section. For revisions, I would preserve useful existing instructions, essential behavior and the user's scope. Completion includes verification and a separate five-iteration automatic refinement review for each changed skill, with its results reported; the review does not authorize promotion of its candidate. This document explains that prospective execution without performing it.

## 2. Process overview

I would read the ordered guidelines and supporting writing guidance before drafting, inventory required behavior, and adapt the annotated template to the actual task. I would replace placeholders, remove authoring comments and unnecessary sections, validate the completed package, then delegate its automatic review. That child establishes intent, simplifies a separate complete candidate, obtains fresh comprehension reviews, corrects misunderstandings and repeats for five iterations. Mutual authoring/refinement dependencies are reading obligations, so internal review changes do not launch another review.
