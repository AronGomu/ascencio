# Explanation from review C for fresh skill comprehension

## 1. Outcome and scope

Improve one supplied target bot through reproducible paired evaluation against frozen opponents, including its starting AI. Deliver the accepted source, verified results and compact history, honestly retaining the starting/accepted source when nothing qualifies. Only target AI may change; decks, engine, legality and hidden-information boundaries remain protected. Optional inputs are opponents, owner limits and a compatible current-format checkpoint.

## 2. Process overview

Prepare frozen identities, limits, analysis policy and separately calibrated match/replay pools; evaluate baseline, then decide and analyze. Replay isolated rules against the selected analysis source, assemble passing edits, evaluate and repeat within authority. Every evaluation receives analysis, including the final candidate. The stateless controller prints stages/edges; owning tools persist execution and accounting, while the orchestrator verifies semantic gates and implements edits. Delegation is limited to loss diagnosis.

## 4. Identities and invariants

| Item | Initial source/value | Allowed changes | Must remain fixed | Verification |
|---|---|---|---|---|
| Comparison | Starting setup | Accepted reference advances strictly on improvement | Opponents, paired starting inputs/order, engine/content/runner | Hashes, paired completed intersection; every opponent represented |
| Scoring | Game outcomes | Ignore finalized incidents symmetrically | Equal opponent weighting; draws denominator/zero wins | Rates/differences/coverage, no confidence intervals |
| Ordinary mode | Accepted source | Add one fix per isolated variant | Analysis/control/assembly share that source | Rejected evaluation still analyzed first |
| Repair mode | Valid regressing candidate | Remove/update one existing rule; add none | Unedited candidate rules; comparator remains accepted | Candidate losses only; new-loss metadata is association |
| Pending rule | Stable reason/rule IDs, aliases, semantic/source hashes | Explicit reconciliation and additional distinct losses | Original provenance/decisions/choices; different correction gets separate identity | Fresh current-analysis-source control plus rule on every accumulated case |
