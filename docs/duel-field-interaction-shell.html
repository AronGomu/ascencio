Prompt routing

One pure function decides. One surface at a time. No component guesses.

promptSurface(prompt, spec, showWorkspace)

prompt === null                                  -> "none"
showWorkspace                                    -> "docked"   // workspace-grid panel
spec active && spec.fieldCapable                 -> "field"    // chips + action bar
otherwise                                        -> "dialog"   // modal PromptControls
stateDiagram-v2
  [*] --> none
  none --> field: prompt with card or zone choices
  none --> dialog: prompt with no field target
  none --> docked: workspace enabled
  field --> none: response accepted
  dialog --> none: response accepted
  docked --> none: response accepted
  field --> dialog: follow-up prompt has no field target
  dialog --> field: follow-up prompt targets cards or zones
Non-negotiable

PromptDialog has no close button, ignores Escape, ignores backdrop clicks. The engine is blocked on a response. Cancelling, where legal, is one of the prompt's own choices.

Priority and phase

Priority is not an engine field. It is derived: a prompt exists and no response is in flight.

hasDuelPriority(prompt, responsePending) = prompt !== null && !responsePending

true  -> green  "Choose Action"
false -> orange "Waiting Opponent"

phase pill = DUEL_PHASE_LABELS[snapshot.phase]
render      = (prio-pill) - (phase-pill)   top-right of the field

Phase labels map the eleven-member DuelPhase union exhaustively: Draw, Standby, Main 1, Battle Start, Battle Step, Damage, Damage Calculation, Battle, Main 2, End, Unknown.

Drag placement contract

The engine ships action and zone in two separate prompts. The UI hides the seam without lying about legality.

StepOwnerRule
Drag startFieldHand card only, actionable, cardAction spec, pointer moved more than 8px
HaloPure mapperplacementZoneCandidates(action, board) — unoccupied monster zones for summon and set-monster, plus both extra monster zones for special summon, unoccupied spell/trap zones for activate and set-spell. Never p0:field.
DropPure mapperdropChoiceForZone — monster zone prefers summon, then special summon, then set; spell zone prefers activate, then set
ArmStorearmPlacementIntent(zoneId) records zone plus the arming prompt id
DispatchStoreOne chooseChoice, normal validation path
ReconcileStoreAuto-answer only a selectPlace prompt with min === max === 1 and exactly one choice mapping to the armed zone
FallbackStoreAnything else clears the intent and renders the real prompt with true highlights
ExpiryStoreIntent cleared on every prompt, result and error; survives state and event

Gesture is pointer-event based, not HTML5 drag-and-drop. jsdom implements neither DataTransfer nor elementFromPoint, so the drop hit test is an injected function and component tests stay deterministic.

Settings model

UiSettingsState { showDuelHud: false, showWorkspace: false }   // both off by default

setShowDuelHud(value)   -> HUD: turn, counts, trays, chain, rich card state
setShowWorkspace(value) -> docked prompt panel + duel log; also flips routing to "docked"
reset()                 -> defaults

In memory, session scoped. Reload resets. No IndexedDB, no localStorage. Diagnostics that lost their old home — engine version, active and fallback snapshot ids — live in the settings dialog.

Selector contract

Every element rendered under src/app/ carries a unique data-cy acting as its variable name. Structural tests select by data-cy; accessibility tests keep selecting by role and accessible name. A static scan of src/app/**/*.svelte fails the suite on a missing or duplicated value. Full rationale in ADR-002.

Test architecture

  • Pure unit — prompt surface, priority, phase labels, action-word map, placement candidates, drop choice, pending placement, settings store, card preview resolver, data-cy scan, stylesheet invariants.
  • Component — dialogs and focus behaviour, action bar dispatches, end-turn enablement, chips keyboard traversal, pills, preview panel lease lifecycle, drag gesture with an injected hit test.
  • Store — arming, auto-answer on a matching selectPlace, no answer on a mismatch, intent expiry.
  • Browser — surrender through the menubar, panels hidden by default, wheel scroll over the field, drag-to-play, preview on hover, field row geometry, keyboard-only duel completion.

TDD order per ticket is unchanged: failing assertion, proven failure, minimum implementation, refactor while green, ticket-scoped aggregate gate.

Preserved constraints

  • Main thread never imports or calls the engine.
  • Presentation state never determines legality. The drag halo is explicitly non-authoritative.
  • One response per prompt. The auto-answered placement is a response to its own prompt, not a second answer to the action prompt.
  • Images never block legal input.
  • No permanent animation loop. Drag adds no per-frame DOM work.
  • Hidden identities never reach plain UI output: cards without a visible identity never populate the preview panel.
