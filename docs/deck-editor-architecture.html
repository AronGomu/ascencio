Deck Editor — target architecture

Post decks-feedback round 2. Supersedes the 2026-08-16 target state. ADRs 036–044.

Surface layout

Full stage width, 0.25rem gutter. Height = var(--stage-h) − header; each pane scrolls inside itself, so shell-region-decks never scrolls above the breakpoint (ADR-042).

Header row: Deck Library · deck name input (= rename) · Duplicate · Export · Set default · Delete · Undo · Redo · Load.

Preview — --preview-w 15.5rem

Shared CardPreviewPanel from src/shell/index.ts (ADR-036), art via staticImageUrl (ADR-039). Width now fits the card image; the duel shares the same token.

Shows hovered ?? selected.

Workspace — minmax(0, 1fr)

Main — 10 cols, 40/50/60 slots, count X/40 → X/40-60
Extra — 15 slots, one row
Side — 15 slots, one row, expanded on open

Whole zone header bar toggles collapse (chevron + heading + count in one full-width button).

Catalog — minmax(16rem,.55fr)

Header: result count + To sideboard checkbox. Filters: name, card type, subtype, attribute, monster type.

Results: 60 tiles per window, +60 per sentinel intersection, overlay scrollbar, lazy images.

Model & storage

  • DeckCommand: add(zone?) · remove · move · import · restore · reorder · sort(alpha|type). Append-at-end, no auto-sort (ADR-037).
  • History = membership multisets. reorder/sort push no history entry and are not undoable — but they do append an autosave entry (ADR-044).
  • ygo-story-decks v2 (ADR-038): decks · histories · preferences (last-opened-deck, default-deck, favourite-decks) · autosaves (global, cap 100).
  • Catalog: runtimeCatalog() fetches 64 card shards + 64 text shards from runtime/assets/current/catalog/…, joins them through packagedCatalog, memoized per page load (ADR-043). 14,794 cards.
  • Search: buildDeckCatalogIndex pre-lowercases names once; filterDeckCatalogIndex filters against it, under measured budgets.
  • Validation: no missing-art warning — art coverage is a build property, not a deck defect.

Library screen

  • One toolbar row: search · sort · Import Deck · Create deck.
  • Row = identity only: name + Default badge on one line, counts and updated below, ★ favourite in the right corner.
  • Order: default deck → favourites → rest, each group by the selected sort (orderDeckLibrary, ADR-040).
  • Row halo carries validation: green valid · orange warnings · red errors; title lists issues.
  • No per-deck actions here — rename, duplicate, export, set default and delete live on #/decks/{id}.

Boundary notes

  • Editor ↔ shell: preview panel, overlay scrollbar and stage context via src/shell/index.ts only.
  • Editor ↔ duel: no direct edge. Both read the same memoized runtimeCatalog(), which is what keeps "assemblable" and "playable" the same set (ADR-043).
  • src/decks/starter-deck.ts imports the bundled player.ydk?raw; never exported from src/decks/index.ts (eager-chunk rule).
  • Every rendered element carries a unique kebab data-cy (enforced).
