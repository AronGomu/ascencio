Bundled Deck Selection Architecture

One source of truth from checked-in .ydk files to build manifests, a pre-duel two-sided picker, strict Worker commands, reproducible matchup identity and a fixed field-layout profile. Editing/importing decks, side-deck flow and progression stay outside this design.

Goals & invariants

One catalog

Stable ids/names/filenames drive browser/Node loading and build coverage.

Derived pool

Every deck code determines metadata, script, text and image packaging.

No auto-start

Ready Worker shows picker. Reload restores highlight only.

IDs over boundary

Main sends validated registry ids, never deck source text.

One duel / Worker

Rematch/change uses replacement Worker; no stale session reuse.

Reproducible pair

Pair-derived preset id enters existing trace beside snapshot/seed/responses.

Engine authority unchanged. Registry chooses card lists. Worker still validates and ocgcore alone decides legality/effects/results.

Worker command & preset identity

type StartDuelCommand = {
  type: "startDuel";
  duelId: DuelId;
  playerDeckId: DeckId;
  opponentDeckId: DeckId;
};

function duelPresetId(player, opponent) {
  return duelId(`bundled-v1:${player}:vs:${opponent}`);
}

createDuelPreset(playerId, opponentId, DECK_SOURCES)
  → { id, playerDeckId, opponentDeckId, player: ParsedDeck, opponent: ParsedDeck }
  • Parser permits only four exact keys.
  • Both deck ids must pass isDeckId.
  • Worker reconstructs pair id and rejects command mismatch.
  • Worker parses/validates selected decks exactly once per Start.
  • Main never sends arbitrary source/path/card list.

Pair id flows into existing DuelTrace.presetId. Snapshot revisions + seed + ordered responses + pair identity remain enough to identify a run.

Validation

Bad JSON/version → full defaults. Unknown deck id or invalid window coordinates fall back independently.

Failure

Storage absence, quota or SecurityError never blocks picker/duel; in-memory state continues.

Coordinates

Field-local CSS px; windows clamp after mount/resize. Not duel state.

Non-goals

No cross-tab sync, migration, expiry or persistence for ADR-009 session settings.

Validation contract

Registry

Six unique ids/files; browser/Node source parity; all `.ydk` parse and respect 40–60/≤15/≤3 constraints.

Build

Every reviewed code has card/text/script/image; build succeeds with recorded bundle delta.

Command/lifecycle

Strict parser, picker no auto-start, pair id match, rematch one start, reset zero starts.

Persistence

Corrupt/throwing storage tests; reload restores highlight only.

Rules/layout

Bit detection exact; MR3/32 vs MR5/34; projected profile frozen; conflict visible; pinned-core mode gate.

User path

Chromium picker→duel→result→rematch/change; one manual duel per new archetype.

No automated deck-specific matchup tests. Automated coverage tests structure: source validity, derived pool, manifest coverage, command flow and layout decision. User manually exercises deck behaviour.
