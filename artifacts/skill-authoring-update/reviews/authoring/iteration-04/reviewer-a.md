# Explanation from reviewer A for prospective skill authoring

## 1. Outcome and scope

I would create or revise the requested skill as a usable package, preserving useful instructions and the user's scope. Inputs are the requested behavior, existing package when applicable, and explicit settings or overrides. Completion includes the authored package and a separately retained five-iteration refinement candidate with evidence. The review grants no installation, publication, promotion, or unrelated implementation authority.

## 2. Process overview

I would read the ordered guidelines and supporting writing guidance, establish the behavior contract, then adapt the annotated template. After checking the authored result, I would dispatch one automatic refinement review for each changed skill. That child would simplify, validate, obtain three fresh comprehension explanations, compare behavior, and correct misunderstandings through five iterations. Review-generated edits stay within that review rather than recursively initiating authoring reviews.
