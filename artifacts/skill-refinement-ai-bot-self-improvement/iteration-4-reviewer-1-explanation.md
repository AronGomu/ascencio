# Explanation from reviewer 1 for refined bot-improvement workflow comprehension

## 1. Outcome and scope

Given a target `ai-bot`, optional extra opponents, owner limits and optionally a compatible checkpoint, seek a higher paired-game win rate and deliver the accepted source, verified results and compact history. Change only target AI while retaining the starting AI among frozen opponents. Success includes an honest unchanged outcome when no edit qualifies; exhausted resources produce an incomplete suspension, not successful delivery. This explanation reads only the refined package and explanation template; linked implementation and external contracts were not inspected.

## 2. Process overview

Prepare pins identities, budgets, schedule and separate concurrency recommendations. Evaluate first measures starting source, then assembled candidates; Decide preserves or advances the accepted reference. Every evaluation proceeds through Analyze, including the final allowed decision and rejected candidates. Analyze dispatches diagnosis-only slices, then Replay tests isolated edits and Assemble combines qualifying ones before another evaluation. A decision ceiling after analysis or no qualifying edit leads to Deliver. Incidents may suspend any active stage; authorized verified continuation restores its prior stage. The executable dispatcher presents instructions and checks named edges; owning project tools and the orchestrator actually execute and verify this process.

## 6. Incidents and continuation

| Incident | Immediate action | Retry allowance | Evidence preserved | Resume condition |
|---|---|---|---|---|
| Individual game/replay timeout | Bug report; finalize ignored; continue safe jobs | Never retry that case | Timeout reason/count, paired exclusion; replay timeout stays associated denominator, never converts | Case settled, not interrupted work |
| Interrupted evaluation | Preserve verified completions; recover missing work within deadlines | Automatic within pinned 10% recovery | Attempts/reservations/timeouts and completed evidence | Remaining resources; after recovery exhaustion ignore missing interrupted games |
| Calibration worker-count failure | Fresh evidence directory, identical inputs | Once; second excludes count and remaining repetitions | Both attempts and retry/exclusion state | Other counts may continue; fully successful required repetitions only |
| Unsupported package format before admission | Preserve validation; change build/validation tooling only; related local checks; fresh validation directory | Narrow tooling exception; no game/recovery charge | Failure and new validation | Stop if still invalid or boundaries cannot hold |
| Initialization/sideboarding/integrity/other non-timeout failure | Stop; never relabel unsafe state ignored | No generic retry | Exact errors and bound evidence | No automatic recovery authorization from dispatcher |
| Analyst failure/owner stop | Halt dispatch; settle/terminate owned analysts | Explicit continuation | Claims, reports, uncovered losses | Resume uncovered work without duplicate owners; stale completions invalid after reassignment |
| Time/storage exhaustion | Stop admission, shutdown/checkpoint/report | Explicit increase/continuation | All resume dependencies, consumed budgets, pending work | Same verified checkpoint, applicable effective limits and authorization |
| Owner pause/cancellation | Stop admission and owned work | Explicit instruction | Verified checkpoint and incomplete status | Same verified checkpoint; explicit closure remains incomplete |
