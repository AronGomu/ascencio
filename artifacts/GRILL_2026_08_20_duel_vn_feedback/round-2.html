1. How does the unmerged deck work land before any worktree is removed?
Nothing has been deleted. Measured state: duel and vn hold no commits that main lacks. deck holds 9 unmerged commits (deck-editor round 2: catalog left-click moves, single-row extra/side zones, whole-art tiles, favourites, autosave position log, e2e realign) and its worktree has 5 uncommitted modified files. Removing worktrees or deleting branches before this lands destroys work.

This is the first ticket of the plan, so it has to be exact about who runs what.

2. Does a story save own its decks as well as its collection?

You wrote “a story save contains its own collection of cards and its own decks”. Decks currently live in one global IndexedDB database (ygo-story-decks v2) with history, favourites and a default-deck pointer; moving them inside the save is a real migration, and it decides how big this plan gets.

3. What does the deck editor show when entered from inside a story save?

The editor is one screen with two possible contexts. You said ownership does not gate deck building yet, so the catalog stays full — but the deck list and the collection viewer still have to know which save they belong to.

4. What does “free play” mean concretely?

“Free play has every card” needs a home. Today the shell has Duel Simulator, Deck Editor and Visual Novel as three peers with no notion of a save context, so “free play” is either the existing two non-story domains or a new explicit mode.

5. Set images: what happens for a set the upstream has no image for?

Confirmed by querying it: db.ygoprodeck.com/api/v7/cardsets.php returns a set_image URL for most sets (images.ygoprodeck.com/images/sets/LOB.jpg, 200 OK) but some sets carry no image key at all. Same host already serves the card art, so the upstream itself needs no further approval.

6. Set images: which storage and verification discipline?

The repo has two established disciplines: the duel’s hash-verified snapshot (engine-critical, Cache Storage, leases) and ADR-039’s plain static runtime URLs for editor art ({BASE_URL}runtime/images/{code}.jpg, browser cache). Set images are decoration — but you asked for “hash-verified like card images”.

7. Which screens use the new zoom-with-text component?

You ruled the existing preview panel out for the click-to-zoom case. But feedback-vn.md also says the set card list should “use the same card preview from duels and decks”, so the two surfaces may want different components — I need the split stated.

8. Where does the drop confirmation menu appear?

Loose end of answer 4: the menu has to be anchored somewhere, and the duel already has two placement patterns — chips above a card, and a floating window anchored to a field element.

9. Duel rewind: edge cases and which errors offer it

You want the rewind to land on the last decision you had agency over. Two edges follow: a failure that happens before you have made any decision this duel, and errors that are not response rejections at all (asset, worker or projection failures, where a replay would reproduce the same crash).
