# Explanation from reviewer C for prospective skill authoring

## 1. Outcome and scope

I would create or revise the requested skill using the candidate authoring package, preserving useful existing instructions and the user's scope. Inputs are the authoring request, existing material when revising, and applicable user settings. Success means a usable authored package plus a separately retained five-iteration refinement candidate and an honest review report. The review cannot replace the authored result. This explanation describes execution without performing authoring or review.

## 2. Process overview

I would read the ordered guidelines and supporting writing guidance, resolve applicable priorities, inventory behaviors, then adapt the annotated template. After validating the authored result, I would dispatch its automatic refinement review. That child establishes an explanation and baseline, simplifies a separate package, checks it, obtains three independent comprehension explanations, and corrects misunderstandings before advancing iterations. Circular authoring references resolve to this candidate; dependency reads do not invoke more workflows.
