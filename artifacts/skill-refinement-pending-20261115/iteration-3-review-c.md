# Explanation from reviewer C for fresh comprehension

## 1. Outcome and scope

Improve one supplied `ai-bot` against frozen opponents, always including its starting AI, using reproducible paired game results. Optional opponents, compatible checkpoint and owner limits customize the run. Only target AI may change; decks, engine, legality and information boundaries stay protected. Success delivers accepted source, verified results and compact history; unchanged acceptance is legitimate when no edit qualifies.

## 2. Process overview

Prepare freezes setup and calibrates execution, then evaluates baseline. Every evaluation proceeds through decision and loss analysis, including the last rejected candidate. Analysis selects an ordinary or regression-repair source; isolated rules undergo replay before combination and another evaluation. No passing rule or the decision ceiling leads to delivery. Resource exhaustion suspends rather than closes. The stateless controller checks edges; owning project tools persist state and the orchestrator verifies semantic gates.

## 5. Limits and accounting

| Resource/stage | Default limit | Override rule | Accounting | Action at exhaustion |
|---|---|---|---|---|
| Decisions/evaluation | 50 decisions; 250 four-game matches | Pin owner limits | Baseline excluded from decisions; distribute matches quotient/remainder | Analyze final evaluation, deliver |
| Games | Planned `(1+effective decisions)×matches×4`; recovery floor 10% | No implicit extension | Failed/interrupted reservations count; caches do not; separate diagnostics | Exhausted recovery ignores remaining interrupted games |
| Time/storage | 24h; 50GB; protected 16MB reserve | Explicit continuation, complete effective limits | Original start includes downtime; logical/imported bytes; locked admission | Suspend, block writes |
| Deadlines | Evaluation 5h; preparation 10m; validation/replay branch 5m; shutdown 60s | Pin effective values; cap by remaining time | Launch-to-exit, replay prefix included | Incident policy |
| Rule stack | 300 distinct losses/rule; eligible at five | No extra run resources authorized | First-seen distinct cases; replay all against current source | Valid complete 300-case failure becomes proven-discarded |

Replay conversion requires intended choice changed and both five winning conversions and 5% of accumulated losses. Below either threshold before 300 remains pending; ignored timeouts stay denominator. Historical outcomes never substitute. Calibration covers worker counts 2 through logical CPUs with successful repetitions or documented exclusions; replay selects smallest within 3% of fastest median.
