# Explanation from reviewer A for prospective refinement execution

## 1. Outcome and scope

I would produce a complete, readable sibling refined skill package preserving the supplied skill’s intended behavior and output contracts. The required input is its folder; optional inputs specify priorities, retained requirements, iteration count, candidate destination and review context. Success requires completing the authorized iterations, resolving comprehension disagreements, and delivering evidence and links without replacing the source. This explanation describes execution only.

## 2. Process overview

I would establish a behavior baseline before simplifying, then alternate candidate edits with verification and fresh comprehension review. Each outer iteration includes an inner correction loop until no misunderstanding remains. Linked authoring guidance supplies deletion audits, boundary checks and accounting obligations; mutual skill references are dependencies rather than recursive invocations. Refinement edits belong to the current review and do not trigger another automatic review.
